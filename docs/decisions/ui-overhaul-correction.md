## The result to build

One coherent application with substantially new screen composition and interactions. Preserve every supported backend operation; reuse the API and sound behavior helpers. Existing routes remain valid. A persistent shell may preserve terminal nodes, but embedding the old layouts is not a redesign.

- Shell: compact masthead with Mission Control, Terminals and Overview navigation; Usage, Review attention, and Settings as global utilities. Remove the old numbered five-item vertical navigation rail. Use accessible text and simple inline icons where useful. No decorative shortcuts-as-icons.
- Terminals: a compact directory/session navigator, large live terminal deck, per-pane focus/close controls, and a bottom session dock with New terminal and Resume. Workspace title is the active directory, not a marketing headline. Toolbar is compact and contextual. Activity/chat opens alongside the active session and starts closed. Keep persistent splits, vertical/horizontal arrangement, resizers, focus/restore, search, uploads, resume, rename, terminate, engine/model selection and connection handling. Empty state has concise instructions and actions. Keep the genuinely liked folded ASCII field from motion-before.html visibly present; no decorative caption or tagline. Give the empty state more of the field and an immediately useful launcher, not a giant slogan.
- Overview: replace the horizontal flow diagram, duplicate plan column, and three engine racks with a work navigator and a substantial selected-work area. Left: searchable work list, filters for active/review/completed and access to archived plans. Each entry shows actual label, state, provider and activity. Right: selected work identity, manual ordered plan, real conversation/tool output and reply composer. Reuse groupByThread, createFullFeed/fetchThread/sendReply, and actual flow/plan contracts. A plan-only item is supported explicitly. Manual plan steps are not a scheduler. Keep archive/unarchive operations and errors visible. No fixtures on API failure.
- Dispatch: New job is a focused composer in the selected-work area, with prompt first, title/directory context and engine/model/isolated-worktree options grouped below. Existing /dispatch deep link opens that composer, not the old permanent form/table split. Submission creates through the current API and selects the real returned job; draft and pending/error feedback must work. No real job executions during verification.
- Review: /review opens the same work interface filtered to reviewable items. Selected item combines actual diff summary, full thread, copy review command, reviewed acknowledgment, and separate guarded worktree landing. Preserve backend eligibility and confirmation behavior. No fabricated diff hunks. No old review table.
- Usage: dedicated lightweight usage surface reachable globally (/lanes?view=usage may be retained). Provider-specific presentations: Claude cost/tokens/reset, GLM 5-hour/monthly quota, Codex availability/auth. No fake common percentage, combined total, hard-coded slot limit, zero substituted for unavailable data, or legacy engine racks. Actual running work may link to Overview.
- Settings: replace the three engine columns and repeated label/value/action rows with readable grouped forms: Connections, Plan/Execute/Review defaults, Access. Native controls, readable labels, help only where needed, clear Save feedback. Reuse existing form contracts, model picker and protected inputs. Unsupported check/auth actions must explicitly say unavailable and never pretend success. Do not render placeholder provider auth as a live fact. Login/setup should share the new identity with simple usable forms.

## Concrete defects from the first pass

1. scripts/render-ui-preview.ts emits bundles under js/client but HTML asks for js/*.js, producing 404. Fix output root and verify every emitted script path exists. Current live server serves old theme tokens from startup; preview must copy current CSS/tokens under fresh preview paths and reference those, with no browser interception needed. Render current actual templates, never a second mock implementation. Config values must not overwrite actual settings accidentally: use actual safe role/model values and configured booleans, never secret values, or make preview-only settings writes clearly unavailable.
2. client/nav.ts looks up #tabs inside embedded pages where it is omitted. Keyboard navigation must still work when focus is in secondary non-input content, and editable targets must suppress shortcuts.
3. client/terminal.ts old socket onclose checks only views.has(id). Reconnect replaces the same ID, so late callbacks act on a disposed view and set stale status. Guard callbacks with current view/socket identity.
4. Zero sessions: Focus, Find and Reconnect need explicit relevant feedback. Opening Find before New terminal currently places the search input over the form's Cancel button. Scope search to the active terminal and close it when it has no usable target; verify actual pointer accessibility.
5. Prior automatic review reproduced broken session rename: selecting a tab immediately rebuilds the tab strip, removing the name node before the second click reaches its double-click handler. Preserve a stable rename target or provide a reliable explicit Rename action in the new session dock; verify the gesture actually opens the editor.
