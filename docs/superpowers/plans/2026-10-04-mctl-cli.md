# mctl: Mission Control from the command line

Goal: every essential Mission Control feature usable from a shell, by a person or an AI agent, with no browser. Plain commands, not a TUI. No ASCII art yet.

## Facts the design rests on (verified 2026-10-04)

- `mc` is taken on this machine (`/opt/homebrew/bin/mc`, Midnight Commander). The command is `mctl`.
- Requests to `127.0.0.1` / `localhost` with no `Origin` and no `sec-fetch-site` header pass `localRequestAllowed` (`server/local-access.ts:37-46`), so a local CLI needs no token for any route.
- Non-local URLs need `Authorization: Bearer <token>` and only reach what `allowToken` permits (`server/auth.ts:9-21`). The token lives in `secrets.json` under `configDir()` (`server/secrets.ts:61`), field `apiToken`.
- All endpoints are in `server/routes/*.ts`. Read each handler's body/query handling before wiring a command; never invent a field.
- Job output streams as SSE from `GET /api/jobs/:id/stream` (`server/routes/jobs.ts:531`, frames built near line 300-390).
- Permission decisions are `allow_once` | `allow_always` | `deny`.

## Files

- `cli/mctl.ts` - `#!/usr/bin/env bun` entry: parse argv with `node:util` `parseArgs`, route to the command table, map errors to exit codes. Export `main(argv, deps)` so tests can call it with an injected `fetch`, `stdout`, `stderr`, `env`.
- `cli/client.ts` - `createClient({ url, token, fetch })` with `get / post / patch / del / stream(path)`. JSON in/out. Throws a typed error carrying HTTP status and the server's `error` string.
- `cli/commands/jobs.ts`, `cli/commands/studio.ts`, `cli/commands/system.ts` - command handlers grouped by domain (keep each under ~400 lines).
- `cli/format.ts` - aligned table printer and relative-time helper for human output.
- `test/cli-*.test.ts` - see Tests.
- `tsconfig.cli.json` - same compiler options as `tsconfig.json`, `include: ["cli/**/*.ts"]`; add `"typecheck:cli": "tsc -p tsconfig.cli.json"` to package.json scripts.
- `package.json` - add `"bin": { "mctl": "cli/mctl.ts" }`. Make `cli/mctl.ts` executable (`chmod +x`).
- `README.md` - one short "Command line" section: install (`bun link` in the repo, then `mctl --help`), `--json`, `MC_URL`, `MC_TOKEN`, exit codes.

## Global behavior

- `--url <u>` > env `MC_URL` > `http://127.0.0.1:7777`.
- Token: env `MC_TOKEN` > `secrets.json` `apiToken` (read the file directly; do NOT call `readApiToken()`, it generates a token as a side effect). Send the Bearer header only when a token exists.
- `--json`: print the server's JSON response exactly, one document on stdout. This is the AI mode; every command supports it.
- Without `--json`: short human output (tables for lists, key: value for single items).
- `--help` / `-h` on the root and on every command group, generated from the command table (single source).
- Exit codes: `0` ok; `1` API error (print the server `error` message to stderr); `2` usage error (unknown command, missing arg, invalid enum value); `3` Mission Control unreachable - stderr says `Mission Control isn't running at <url>. Start it with: bun run start`.
- Unknown flags are a usage error (parseArgs `strict: true`).

## Commands

Each line: command -> endpoint. Bodies and query params come from reading the handler.

System (`cli/commands/system.ts`)
- `mctl status` -> `GET /api/health`, `/api/quota`, `/api/roles` (one summary: up/down, usage per provider, role -> engine/model)
- `mctl roles` -> `GET /api/roles`; `mctl roles set <plan|execute|review> <engine> [--model M]` -> `POST /api/roles`
- `mctl models` -> `GET /api/models`; `mctl providers` -> `GET /api/providers`
- `mctl history [--limit N]` -> `GET /api/history`
- `mctl outcomes` -> `GET /api/outcomes`
- `mctl attention` -> `GET /api/attention`; `mctl attention dismiss <key>` -> `POST /api/attention/:key/dismiss`
- `mctl terminals` -> `GET /api/terminals`; `mctl terminal new [...]` -> `POST /api/terminals`; `mctl terminal rename <id> <name>` -> `PATCH /api/terminals/:id`; `mctl terminal close <id>` -> `DELETE /api/terminals/:id`; `mctl terminal thread <id>` -> `GET /api/terminals/:id/thread`; `mctl terminal sessions` -> `GET /api/terminals/sessions`
- `mctl connections` -> `GET /api/studio/connections`; `mctl connection probe <id>` -> `POST /api/studio/connections/:id/probe`
- `mctl flow-approval` -> `GET /api/flow-approval`; `mctl flow-approval set <value>` -> `PUT /api/flow-approval`

Jobs and chat (`cli/commands/jobs.ts`)
- `mctl jobs [--limit N]` -> `GET /api/jobs` (table: id, status, engine, age, first line of prompt)
- `mctl job new "<prompt>" [--engine E] [--model M] [--cwd DIR] [--follow]` -> `POST /api/jobs`. Prompt may also come from stdin when the argument is `-`. `--follow` then streams like `job follow`.
- `mctl job show <id>` -> job from `GET /api/jobs` plus `GET /api/jobs/:id/activity`
- `mctl job log <id>` -> `GET /api/jobs/:id/log`
- `mctl job follow <id>` -> `GET /api/jobs/:id/stream` (SSE): print text as it arrives, stop on the terminal event; exit `0` if the job finished ok, `1` if failed/killed. With `--json`, print each SSE data payload as one JSON line (NDJSON).
- `mctl job reply <id> "<text>"` -> `POST /api/jobs/:id/reply`
- `mctl job permission <id> <allow_once|allow_always|deny>` -> `POST /api/jobs/:id/permission` (other enum values: exit 2)
- `mctl job kill|land|undo|reviewed <id>` -> `POST /api/jobs/:id/<verb>`
- `mctl job rename <id> ...` -> `PATCH /api/jobs/:id` (only the fields the handler accepts)
- `mctl job export <id>` -> `GET /api/jobs/:id/export.md` (raw markdown to stdout)
- `mctl job thread|commands <id>` -> matching GET
- `mctl job queue <id>` -> `GET /api/jobs/:id/queue`; `mctl job queue rm <id> <itemId>` -> `DELETE /api/jobs/:id/queue/:itemId`

Studio (`cli/commands/studio.ts`)
- `mctl workflows` -> `GET /api/studio/workflows`; `mctl workflow revisions <id>` -> `GET /api/studio/workflows/:id/revisions`
- `mctl policy` -> `GET /api/studio/policy`
- `mctl runs` -> `GET /api/studio/runs`; `mctl run show <id>` -> `GET /api/studio/runs/:id`
- `mctl run start <workflowId> [...]` -> `POST /api/studio/runs`
- `mctl run stop|retry|approve|reject|pause|resume|changes <id> [...]` -> `POST /api/studio/runs/:id/<verb>`
- `mctl run step <runId> <nodeId>` -> `GET /api/studio/runs/:id/steps/:nodeId`; `mctl run step <runId> <nodeId> --post ...` -> `POST` same path (read the handler for what it takes); `mctl run remind <runId> <nodeId>` -> `POST .../remind`

Out of scope for this pass (say so in `--help` footer, nothing else): secrets reveal/rotate/write (would print or change credentials), connection create/delete, drafts/preview/studio default/workflow editing (design-time UI), chat/home and chat/files (UI helpers), job images, terminal drops, attention/studio event streams, interactive terminal attach.
